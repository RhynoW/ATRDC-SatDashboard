# ATRDC SatDashboard 操作手冊（v0.1.29）

> 適用版本：Rust 單機版 v0.1.29（2026-11-26）與線上網頁版。
> 對象：第一次使用本系統的分析人員；不需要寫程式。

---

## 一、系統簡介

SatDashboard 是太空態勢儀表板：在 3D 地球上顯示全目錄衛星的即時位置，並提供近距離配對篩選、覆蓋分析、Starlink 分析、故事頁、「會合與機動實驗室」（碰撞機率、避碰決策、近距離操作模擬），以及衛星管理（更名、群組、再入與目錄異動）、過頂預報、觀測與身分驗證。

有兩種使用方式，畫面與操作大致相同：

| 版本 | 怎麼開 | 差異 |
|---|---|---|
| 線上網頁版 | 瀏覽器開 https://rhynowu-atrdc-satdashboard.hf.space/ 或多語版 https://rhynowu-atrdc-satdashboard-i18n.hf.space/ | 不需安裝。衛星管理的更名與群組、觀測資料**只存在自己的瀏覽器**，沒有帳號與複核紀錄；過頂預報一次最多 300 顆；沒有「衛星任務規劃」「太空小遊戲」與線上更新 |
| Rust 單機版（Windows） | 下載 exe 雙擊執行 | 離線可用；資料存在本機、可多人共用並設帳號權限；多了「衛星任務規劃」「太空小遊戲」、網路圖磚面板、星歷一鍵重抓、自動更新 |

## 二、單機版下載與安裝

1. 依電腦架構下載執行檔（不確定時：設定 → 系統 → 關於 →「系統類型」）：
   - Intel／AMD：[SatDashboard-x64.exe](https://huggingface.co/datasets/RhynoWu/Rust_SatDashboard/resolve/main/exe/SatDashboard-x64.exe)
   - ARM64（Snapdragon 等）：[SatDashboard-arm64.exe](https://huggingface.co/datasets/RhynoWu/Rust_SatDashboard/resolve/main/exe/SatDashboard-arm64.exe)
2. 把 exe 放進一個**新的空資料夾**（例如 `D:\SatDashboard\`）。
3. 雙擊執行。若 Windows 跳出 SmartScreen，按「其他資訊」→「仍要執行」。
4. 會開啟一個黑色主控台視窗，並自動開啟瀏覽器（預設 `http://127.0.0.1:5013/`；埠被占用時自動往後找）。
5. 第一次使用時，程式會自動下載衛星資料庫（壓縮檔約 100 MB，解壓後約 250 MB），主控台每 10% 顯示進度，完成後頁面自動重新整理。

> **結束程式**：關閉主控台視窗，或在視窗內按 Ctrl+C。關閉瀏覽器分頁不會結束程式。

### 資料夾結構

```
D:\SatDashboard\
  SatDashboard-x64.exe
  data\DB\space_db_slim.duckdb     ← 資料庫（自動下載；內含 TLE、SATCAT、GCAT、SATCAT 異動、SupGP）
  data\user_private\               ← 本機私有資料（不上傳，請定期備份）
      accounts.json                  帳號與密碼雜湊
      sat_custom.json                自訂名稱、群組、操作紀錄
      observations.json              觀測資料（地面 POI、觀測、軌道解、身分主張）；地面 POI 也是過頂預報的中心點
      spacetrack.json                Space-Track 帳號（明文，選用）
      ephemeris\                     星歷重抓的覆蓋層
  logo.png                         ← 選用：右下角自訂 Logo
```

每次寫入 `sat_custom.json`、`observations.json` 時都會保留上一版 `.bak`。

### 啟動參數（進階）

在命令提示字元執行 `SatDashboard-x64.exe --help` 可看完整說明。常用的有：

| 參數 | 說明 |
|---|---|
| `--port 5020` | 指定 HTTP 埠 |
| `--host 0.0.0.0` | 讓區網其他電腦連入（預設只有本機）；區網電腦請用 IP 位址連線（例：`http://192.168.1.20:5013/`） |
| `--allow-host <電腦名稱>` | 區網要用電腦名稱（例：`http://my-pc:5013/`）連線時加入；可重複。為防止惡意網站冒用，只接受 localhost、IP 位址與這裡列出的名稱 |
| `--no-browser` | 啟動後不自動開瀏覽器 |
| `--no-update` | 不自動檢查更新（頁面上仍可手動檢查） |
| `--db <檔案>` | 指定資料庫檔 |

### 3. 左側面板：搜尋與分類

- **搜尋欄**：輸入 NORAD 編號或衛星名稱（例如 `25544` 或 `ISS`），從清單點選即可在地球上定位並顯示軌道。自訂名稱（第六節）也能搜尋。
- **分類頁籤**：國家、用途、年代、星座。點選一個分類即只顯示該類衛星；按「返回」回到上一層。
- **底圖與向量圖層**：可開關全球國界、SSN 地面觀測站、📍 地面 POI、🚢 AIS 船舶等圖層（單機版預設底圖為「地形＋海底地形」）。
- **📍 地面 POI**：顯示自己建立的觀測站（青色）與關注地點（橘色）並標上名稱；有設範圍半徑的畫出範圍圈。點選 POI 可看座標、高度、半徑與備註，並可開啟「觀測與身分驗證」或「過頂預報」。圖層下方顯示 POI 數量；POI 有變動時，取消再勾選即重新載入。

### 4. 地球操作

| 操作 | 方式 |
|---|---|
| 旋轉 | 滑鼠左鍵拖曳 |
| 縮放 | 滾輪 |
| 傾斜視角 | 右鍵或中鍵拖曳 |
| 回到台灣上空 | 右上角 🏠 按鈕 |
| 查看衛星資訊 | 點選衛星點 |

點選衛星後，資訊卡列出 NORAD、國家、用途、年代與高度。若目錄名稱還是 OBJECT A 這類暫名，或 Space-Track、建議名稱、自訂名稱有新資訊，下方會多一段「**名稱查詢**」：

| 列 | 內容 |
|---|---|
| 正式名稱 | Space-Track 已正式命名、但 TLE 目錄還沒更新時顯示（例如 NORAD 46232：目錄為 OBJECT A，正式名稱 GAOFEN 9 05）；尚未命名時顯示「Space-Track 尚未命名」 |
| 建議名稱 | 第六節的建議名稱與證據等級、可信度 |
| 自訂名稱 | 在衛星管理設定的名稱 |
| 發射群組 | 國際編號、發射日期與火箭 |
| 注意 | 例如同次發射多顆酬載、A/B/C 與個別衛星的對應尚未建立 |

按「🗂 衛星管理」可到衛星管理頁進一步查詢或套用名稱；有發射群組時另有「🚀 一箭多星」，可直接分析同一次發射的所有物體（第九節）。

### 5. AIS 船舶圖層

1. 左側「向量圖層」勾選「🚢 AIS 船舶」才開始連線，閒置 10 分鐘自動斷線。
2. 船隻依航向與船型顯示，預設只顯示航行中的船；點選船隻看船名、航速、目的地、資料來源與收到時間，以及近 6 小時航跡。
3. 兩個來源以 MMSI 合併、較新回報為準，可在圖層面板只勾選其中一個：
   - **aisstream.io**：需要免費金鑰（到 aisstream.io 以 GitHub 登入申請）。單機版可在圖層面板直接輸入金鑰，只接受在本機設定。
   - **航港局「臺灣海域船舶動態資訊系統」**：台灣周邊約 9,000 艘，每 60 秒更新，不需金鑰。單機版預設開啟；線上版主機在海外連不到，預設關閉。

> AIS 是船舶自主回報，只有岸基接收站約 15～40 浬內有資料；遠洋沒有資料，位置也可能遭干擾或偽造。

## 四、NORAD 監測與軌道六參數

### NORAD 監測

1. 按頂端「🎯 NORAD 監測」開啟面板。
2. 輸入要追蹤的 NORAD 編號，可同時追蹤多顆；按鈕旁的數字是目前追蹤顆數。
3. 被追蹤的衛星會在地球上醒目標示，面板列出即時位置。

### 軌道六參數

1. 按「📡 軌道六參數」開啟調整器。
2. 可先選預設案例：ISS 國際太空站、GPS 中軌、地球同步軌道、Molniya 大橢圓。
3. 拖曳六個滑桿：半長軸 a、離心率 e、傾角 i、升交點赤經 Ω、近地點幅角 ω、真近點角 ν。每個參數旁有白話說明。
4. 面板即時顯示遠地點高度、近地點高度、軌道週期。
5. 「STK Connect 指令」區塊依目前參數自動產生指令，按「複製指令」可直接貼到 STK 主控台。

## 五、其他分析頁

### 台北覆蓋分析（/taipei）

- 即時或指定時刻，有哪些衛星可看到台北；未來過頂預報清單。
- 天球圖顯示過頂軌跡（方位／仰角）；衛星凌月（經過月面或日面）預報。

### Starlink 分析（/starlink）

頁面上方分頁：

- **台灣服務分析**：指定地點的可見衛星數、往返延遲（RTT）、遮蔽評估。
- **顆數普查**：各殼層與世代的在軌數量。
- **V3 佈署**：V3 衛星的發射與佈署進度。
- **離軌名單**：正在降低軌道的衛星與再入預測。

### RPO功能測試（/rpo）

- 選一組近距離配對，以歷史 TLE 重建兩顆衛星的相對接近過程（3D），顯示 RTN 分量與 Chan 碰撞機率。
- 可切換以任一顆衛星為視角中心；`/rpo/cases` 為案例總覽。

### StoryMap（/story）

- 故事清單頁列出所有敘事頁，點選卡片進入。
- 每個故事整合地圖、統計圖與說明，例如星系生命週期、日本發射、海陸空天整合展示。

## 六、衛星管理（/satadmin）

從主選單「🗂 衛星管理」進入。上方分頁：衛星更名、群組分類、衛星失能（DECAY）、SATCAT 異動、星歷資料；單機版另有帳號管理、操作紀錄，線上版另有備份與匯入。

> **資料存放**：單機版存在本機 `user_private\sat_custom.json`，全組織共用，依帳號權限修改（第十三節）。線上版**只存在自己的瀏覽器**，不上傳伺服器；換電腦、換瀏覽器或清除網站資料就會消失，請定期到「備份與匯入」下載備份。

### 1. 衛星更名

1. 「查詢衛星」輸入 NORAD 編號（可多個，以逗號或空白分隔），或名稱、國際編號關鍵字，按「查詢」。
2. 結果表列出名稱、Space-Track 原名、國際編號、TLE 曆元、國別／用途、所屬群組與狀態標籤（已再入、TLE 停更）。
3. 按「更名」輸入自訂名稱與備註後儲存；原名保留，按「還原」即恢復。單機版約 1 秒後全系統（地球儀、搜尋、報表）改用新名稱；線上版只套用在衛星管理與過頂預報的輸出。
4. 「列出重複名稱」找出 OBJECT A、TBA - TO BE ASSIGNED 等同名衛星，可勾選排除碎片與火箭殘骸；點名稱列出全部 NORAD。
5. CSV 批次匯入：欄位 `norad_id,name,group,note`；name 空白＝不改名，group 以「/」分層（例：`PRC偵察衛星/光學`），沒有的群組自動建立。Excel 請另存為「CSV UTF-8」。

### 2. 建議名稱（OBJECT A/B/C…）

新發射的衛星常以「OBJECT A、B、C…」編目，正式名稱要等 Space-Track 公布。建議名稱依可靠度提出候選名稱：

| 狀態 | 意義 | 可信度 |
|---|---|---|
| official | Space-Track 已正式命名（只是 TLE 目錄還沒更新） | 高 |
| inferred | GCAT 逐顆判讀，或該次發射只有一顆酬載 | 中 |
| group_inferred | 只能確認是哪次發射的一員，命名為「XX 群組衛星（推論）」，**不指派 A/B/C 個體** | 低 |
| conflict | 來源矛盾或類型不一致（例如 Space-Track 已判定為碎片） | — |

1. 按「列出目錄中所有 OBJECT x 的建議」，或在查詢結果按某顆的「建議名稱」。
2. 每筆列出發射群組（旁邊的 🚀 可開啟一箭多星分析）、候選任務、個體對應三層判讀，以及注意事項（非酬載、類型不一致、A/B/C 未對應）。任務類型與用途一律不自動歸因。
3. 可修改建議名稱；可加額外證據連結（例如 SeeSat-L 討論串）與複核狀態。
4. 勾選要套用的項目（「勾選 official／inferred」只勾沒有警示的），按「套用勾選的建議」。名稱狀態、可信度、證據連結與原始建議名稱都會存進更名紀錄。
5. 日後 Space-Track 正式命名或 GCAT 名稱變動時，「狀態」篩選選「可升級／有變動」即可找出。

> GCAT 資料：Jonathan C. McDowell, General Catalog of Artificial Space Objects（planet4589.org，CC BY 4.0）。GCAT 的逐顆資料約落後數個月，較新的發射多半只能得到 group_inferred。

### 3. 群組分類

- 可多層，例如「PRC偵察衛星 → 光學／雷達／電子偵察」。左側選群組，右側編輯名稱、上層群組、顏色、感測器類型、偵照角度與備註。
- 感測器類型與偵照角度（離天底角）未設定時沿用上層；過頂預報會用到這兩個設定。
- 成員：輸入 NORAD 編號加入，勾選後移除。刪除群組不影響衛星本身與更名。

### 4. 衛星失能（DECAY）

- **群組衛星狀態**：選群組（含子群組）按「列出」，標出「已再入」（SATCAT 有 DECAY 日期）、「TLE 停更」（超過 N 天沒有新曆元，預設 30 天）與「SATCAT 查無」，附 DECAY 日期、發射日期、在軌天數、最後 TLE 曆元，可匯出 CSV。
- **全目錄近期再入**：列出近 N 天再入的物體。
- SATCAT 跟著資料庫每日更新，不必另外下載。

### 5. SATCAT 異動

列出 Space-Track 編目資料每天的異動（近 1～90 天）：

| 類別 | 意義 |
|---|---|
| 正式命名 | OBJECT x 改為正式名稱 |
| 更名 | 其他名稱變更 |
| 再入／再入日期修正 | 新增或修正 DECAY 日期 |
| 新編目 | 新加入目錄的物體 |
| 類型變更 | 物體類型改變（例如 UNKNOWN → PAYLOAD；由每日快照比對得出） |
| 其他欄位 | 國家、國際編號、發射日變更 |

- 可依類別篩選，或勾選「只看已更名或群組內的衛星」。摘要列的類別數字可直接點選。
- 已套用推論名稱、但 Space-Track 已正式命名的衛星標「**可升級**」，按「建議名稱」可直接改用正式名稱。TLE 目錄仍顯示 OBJECT x 時也會註明。
- 可匯出 CSV。

### 6. 星歷資料

- 顯示最後更新時間、資料庫、最近重抓、目前目錄曆元分布（中位數、1 天內／3 天內／超過 30 天的顆數）與 SATCAT 狀態。
- **一鍵重新抓取**（單機版需管理者）：
  - CelesTrak（免帳號）：抓現役衛星群組，群組成員不在其中的另外逐顆補抓（每次最多 30 顆）。
  - Space-Track（需帳號）：抓全目錄未再入、30 天內曆元的物體。帳號可在頁面輸入（**明文**存在 `user_private\spacetrack.json`），或設環境變數 `SPACETRACK_USER`／`SPACETRACK_PASS`。
  - 新抓的 TLE 只在曆元比資料庫新時採用，資料庫檔本身不變。
  - 依兩站規範限制頻率：CelesTrak 每 2 小時、Space-Track 每 1 小時一次；連線失敗只冷卻 10 分鐘。
- 線上版重新抓取需要管理權杖（Admin Token），一般使用者只看更新時間。

### 7. 帳號管理、操作紀錄（僅單機版）、備份與匯入（線上版）

- 帳號管理見第十三節。
- 操作紀錄：誰在何時更名、改群組、匯入（最近 500 筆）。
- 線上版「備份與匯入」：CSV（與單機版相同格式）與完整 JSON 備份，可在兩版之間搬移資料。

## 七、過頂預報（/forecast）

從主選單「📅 過頂預報」進入，輸出 CSV，不做視覺化。

1. **中心點與預報範圍**：中心點和第八節的**地面 POI 是同一份清單**。
   - 開頁時自動帶入類型為「關注地點」的 POI（還沒有任何關注地點時帶入台北）。
   - 「從地面 POI 加入」選單列出全部 POI（含觀測站），選好後按鈕加入；也可按「＋ 新增中心點」直接輸入名稱、緯度、經度、高度與範圍半徑（最多 30 個）。
   - 半徑 0＝只看中心點；半徑大於 0 時，衛星偵照範圍與該圓形區域有交集就算可偵照。
   - 「儲存為常用中心點（寫入地面 POI）」依名稱寫回：同名的 POI 更新座標、半徑與備註（保留原類型），新名稱新增為關注地點（單機版需編輯者以上）。從表格刪掉的列不會刪除 POI，要刪除請到「觀測與身分驗證 → 地面 POI」。
   - 舊版存的常用中心點，在第一次開啟新版時自動轉成關注地點（同名的略過）。
2. **衛星**：勾選群組（第六節），或另外輸入 NORAD 編號。線上版一次最多 300 顆。
3. **時間與判定條件**：
   - 開始時間（空白＝現在）、預報天數（最多 62 天，預設 31 天）、CSV 顯示的時區。
   - 仰角門檻：中心點看衛星的最低仰角，預設 10°，定義過頂時段。
   - 偵照角度：中心點相對衛星的離天底角在此角度內才算可偵照，可選 15° 或 30°。未勾選「所有衛星一律用此角度」時，群組有設定就用群組的。500 km 高度時 15° 約對應地面半徑 135 km、30° 約 290 km。
   - 只輸出可偵照：只列偵照範圍涵蓋中心點或區域的過頂。
   - 日照篩選：光學衛星只保留日照時段、全部衛星只保留日照時段，或不篩選（全部列出並標示）；太陽仰角門檻可調。
   - 歷史誤差估算：用資料庫近 N 天（預設 60 天）的 TLE 估算預報誤差。
4. **衛星屬性**（簡要版輸出用，頁面上方可展開）：逐顆填寫「衛星隸屬」與「解析度」。
   - 衛星隸屬空白時，依系統國別分類（中國顯示為「中共」）；分類為「其他」或「不明」的新發射衛星改用 SATCAT 擁有者代碼（PRC→中共）。
   - 解析度沒有公開資料來源，請自行填寫（例：判優於1公尺）。
   - 可匯入匯出 CSV，欄位 `NORAD,名稱,衛星隸屬,解析度,備註`；匯入時依 NORAD 合併（名稱欄忽略），匯入後按「儲存屬性表」。
   - 單機版存在本機 `user_private\sat_attrs.json`（需編輯者以上才能儲存）；線上版存在自己的瀏覽器，計算時隨請求送出、伺服器不保存。
5. 按「開始計算」，完成後下載三個 CSV：
   - **過頂清單**：起訖時刻、TCA、最高仰角、可偵照起訖、偵照地面半徑、TCA 當下太陽仰角與日照、當日日出日落、預估時間誤差（p90）。
   - **日出日落**：每個中心點每天的日出、日落（以 −0.833° 計，含大氣折射與日面半徑）。
   - **歷史誤差**：同一顆衛星的 TLE 兩兩比對，依提前 1、2、3、5、7、10、14、21、30 天統計位置與沿軌時間誤差（中位數、p90）。
6. **簡要版 CSV**（依客戶樣本格式，只列可偵照的過頂，時間依所選時區）：
   - **簡要版 A**：經過日期、衛星隸屬、衛星種類、國際名稱、解析度、開始時間、結束時間，另附 NORAD、中心點。同一天內依電子偵察、光學、雷達、其他的順序排列，各類再依時間排序。
   - **簡要版 B**：經過日期（例：12月1日）、國際名稱、過頂時間（例：0627-0630，時分）、種類，另附 NORAD、中心點，依時間排序。
   - 國際名稱＝目前顯示名稱（到「衛星管理」更名為中文即以中文輸出）；衛星種類＝群組的感測器類型（直接輸入 NORAD 的衛星沒有群組，此欄空白）；開始／結束＝可偵照時段。
   - 地球同步軌道衛星會持續涵蓋，時段可能長達數小時（受日照篩選截斷）。

> TLE 外推越遠誤差越大；歷史誤差 CSV 可看出每顆衛星提前幾天預報時的實際誤差量級。

## 八、觀測與身分驗證（/obs）

從衛星管理頁頂端「🔭 觀測與身分驗證」進入。用途：把自己或業餘觀測者（SeeSat-L、SatTrackCam 等）的觀測、軌道解與身分線索整理起來，和目錄 TLE 交叉比對，協助判斷 OBJECT A/B/C 各是哪顆、軌道是否異常。

> **資料存放**：單機版存在本機 `user_private\observations.json`；檢視者可查看與執行交叉驗證，編輯者可新增、修改、刪除與匯入，**管理者才能複核**。線上版只存在自己的瀏覽器，交叉驗證時資料送到伺服器計算後即丟棄，請到「匯入匯出」下載 JSON 備份。

### 1. 四種紀錄

| 分頁 | 內容 |
|---|---|
| 地面 POI | 觀測站與關注地點：名稱、緯度、經度、海拔（m）、範圍半徑（km，過頂預報用）。觀測紀錄以名稱對應觀測站；被觀測紀錄使用中的 POI 不能刪除或改名。同一份清單也是過頂預報的中心點，並可在地球儀「📍 地面 POI」圖層顯示 |
| 觀測紀錄 | NORAD、觀測站、時間（UTC）、方向（RA/Dec J2000，或方位角＋仰角）、星等、觀測者、來源類型與連結 |
| 軌道解 | TLE 兩行（支援 NORAD ≥ 100000 的 Alpha-5 編號，例如 A1419＝101419）、來源類型與名稱 |
| 身分主張 | 「NORAD X 是某某衛星」：名稱、來源類型（官方、GCAT、業餘觀測、自行觀測、新聞、其他）、可信度、連結 |

每筆紀錄都有複核狀態（未複核、已接受、有爭議、已否決），附複核說明、複核者與時間。**內容修改後會自動退回「未複核」**。業餘觀測屬中等可信度來源，需要人工複核後再採用。

### 2. 輸入方式

- 各分頁按「新增」逐筆輸入，或按「編輯」修改。
- 「匯入匯出」分頁：選檔案或直接貼上 CSV，依標題列自動判斷種類（含 `line1`＝軌道解、`station`／`time`＝觀測紀錄、`lat`＝地面 POI、`norad`＋`name`＝身分主張）。**觀測紀錄的觀測站要先建好地面 POI**。格式有誤的列會標出列號與原因，其他列照常匯入。
- 可下載四種範本與匯出 CSV。

### 3. 交叉驗證

在「衛星摘要」分頁按「執行交叉驗證」。資料有變動時請重新執行。

| 項目 | 方法 | 判定 |
|---|---|---|
| 觀測殘差 | 用目錄 TLE（與已登錄的軌道解）算出觀測當下從觀測站看到的方向，與實測方向比較角距 | ≤ 0.5° 符合、≤ 2° 勉強符合、其餘不符合 |
| 同次發射比對（觀測） | 同一次發射的所有物體都算一次，列出最符合的前 5 名 | 最符合者不是所標的 NORAD 時提示 |
| 軌道比對 | 軌道解與目錄 TLE 在軌道解曆元前後 12 小時（每小時一點）的最大位置差 | ≤ 10 km 一致、≤ 50 km 接近、其餘不一致 |
| 同次發射比對（軌道） | 同一次發射中軌道最接近的物體 | 用來判斷 OBJECT A/B/C 各是誰 |
| 身分主張 | 與 Space-Track 正式名稱、同一顆衛星的其他主張比對 | 與正式名稱相同／不同、有其他主張 |

衛星摘要每顆列出：

- **身分**：已確認（Space-Track 已正式命名，或已接受的高可信度主張）、可能（已接受的中低可信度主張）、有主張（未複核）、有爭議（多個不同名稱）、未知。
- **軌道**：與目錄一致／接近／不一致、只有獨立軌道解、只有目錄 TLE。
- **觀測**：符合、部分符合、勉強符合、不符合、無觀測。
- **任務／能力**：一律「未知」，系統不自動歸因。
- 分層判讀：發射群組（國際編號，可信度高）→ 候選任務（身分主張，可信度中）→ 個體（正式名稱或已複核的主張）。點一列看該衛星所有紀錄與驗證明細。

> RA/Dec 請填 J2000；方位角與仰角為站心座標，未修正大氣折射。目錄 TLE 曆元與觀測時間相差超過 7 天時會提示，預測誤差可能偏大。

## 九、一箭多星軌道驗證（/launch）

從衛星管理頁頂端「🚀 一箭多星」、建議名稱清單的 🚀，或地球儀資訊卡的「🚀 一箭多星」進入。用途：一次發射放出多顆衛星時，從軌道資料找線索，判斷 OBJECT A/B/C 各是哪一顆、哪些是酬載、哪些是火箭體或碎片。

1. 輸入國際編號（例如 `2026-260`）或任一成員的 NORAD 編號，按「分析」；也可以點上方「近期多物體發射」清單（可選近 30～365 天）。
2. 摘要列出發射日期、火箭與任務（GCAT），以及目錄中的物體數、軌道群數、偵測到升軌的顆數、SupGP 吻合顆數、已不在目錄的物體。

### 軌道群與沿軌排序

| 欄位 | 說明 |
|---|---|
| 軌道群 | 傾角差 ≤ 0.5°、升交點赤經差 ≤ 2°、平均高度差 ≤ 50 km 歸為同一群；群標題列出物體數、傾角、升交點、高度範圍與物體類型 |
| 順序、Δu | 以所有成員中最新的 TLE 曆元為共同時刻，群內以最小 NORAD 為參考星，比較緯度幅角差 Δu；正值在前方，依此排出沿軌順序 |
| 距參考 | 共同時刻與參考星的直線距離 |
| 漂移 | 相對參考星的平均運動差換算成每日相位變化；正值表示逐漸往前拉開 |
| B* | TLE 阻力項；面質比大的碎片、火箭體通常較大 |

### 歷史演化（升軌偵測）

- 用資料庫的歷史 TLE（共同時刻前 120 天內；資料庫保留最近約 16 天的完整紀錄）計算每顆的半長軸與近地、遠地高度，畫出平均高度歷史圖（顏色＝軌道群）。
- 相鄰兩筆 TLE 間隔 ≤ 5 天、半長軸增加超過 1 km，判為**升軌機動**：大氣阻力只會讓軌道降低，軌道升高代表有推進的主動酬載。
- 間隔 ≤ 2 天、半長軸減少超過 5 km 判為**降軌**；其餘依近 14 天的斜率判為**自然衰減**（每天降低超過 0.05 km）或**穩定**。

### SupGP 身分比對

- SupGP 是營運商自行提供給 CelesTrak 的補充星曆（Starlink、OneWeb、Planet、Kuiper、Iridium、SES 等，資料庫每日更新）。同發射或軌道相近的星曆傳播到該物體目錄 TLE 的曆元比較位置：≤ 25 km **吻合**、≤ 100 km **可能**。
- 只涵蓋有公布星曆的業者。例如福衛系列沒有 SupGP，會顯示「**無對應 SupGP**」，括號裡最近的候選只是同批或軌道相近的其他衛星，距離沒有身分意義。
- **編號不一致**：吻合到的 SupGP 編號與目錄不同時會提示。若本物體編號的 SupGP 星曆又正好落在那個編號的目錄位置，標為「**疑似目錄編號互換**」：同軌道面、相距很近的兩個物體，地面追蹤可能把編號對調（cross-tag）。SupGP 來自業者的星載 GPS，通常較可信，但仍需人工確認。

> 分群、排序與 SupGP 比對都是判斷身分的線索，不等於身分確認；任務類型與能力不自動歸因。

## 十、會合與機動實驗室（/lab）

從主選單按「🧪 機動實驗室」進入。頁面上方有四個分頁，右上角可切換語言、按「返回主頁」。

> **重要觀念**：TCA 與距離顯示的位數代表數值求解精度，不代表預報準確度。公開 TLE 在低軌道的誤差約為公里級；頁面上的協方差若是「展示模式」，碰撞機率只在該假設下成立。

### 1. 批次分析

用途：一顆主星對多顆次星，在指定期間內找出所有近距離交會並計算碰撞機率。

1. **主星 NORAD 編號**：例如 `25544`。
2. **起始時刻（UTC）**、**分析天數**（最多 7 天）。
3. **篩選門檻（km）**：只列出距離低於門檻的交會。
4. **次星清單**：每行一個 NORAD 編號（最多 200 顆）；或按「載入 CSV 檔」，表頭為
   `norad_id,name,line1,line2,hbr_m,sigma_r_km,sigma_t_km,sigma_n_km`。按「檢查清單」先確認格式，錯誤會標出行號與原因。
5. 可調整粗掃步長、預設硬體半徑（m）、主星與次星的 RTN σ（km）。
6. 按「執行分析」。

結果：

- 上方摘要：分析配對數、門檻內事件數、最大 Pc（Foster）、最近距離、計算時間。
- **事件表**：TCA、次星、距離、相對速度、RTN 分量、接近角、Pc（Foster／Chan）、適用性。點選一列看詳細資料。
- **適用性**三種結果：通過初步篩選、未通過初步篩選、無法判定。未通過時，短時交會假設不成立，Pc 僅供參考。
- 圖表：距離歷程（對數刻度）、交會平面（B-plane，藍色橢圓為合併協方差 1σ／2σ／3σ，紅圈為合併硬體半徑）。
- 「下載事件 CSV」「下載完整 JSON」可保存結果。

### 2. 場景 JSON

用途：以標準場景檔（`satdash.scenario/v1`）描述物件、期間與協方差，執行完整分析。

1. 從「示範場景」選一個範例，或按「載入 JSON 檔」。
2. 直接在編輯框修改 JSON。
3. 按「執行分析」。格式錯誤時顯示錯誤代碼與位置。

協方差有兩種模式：**展示模式**（固定 RTN σ）與**傳播模式**（6×6 協方差沿軌道傳播，較接近實際）。

### 3. 避碰決策

用途：針對一個交會事件，搜尋沿軌道方向（加速或減速）單次推力的避碰方案。

1. 選「示範案例」（例如「基準：可行」「Δv 預算不足」「二次篩選拒收最省方案」）。
2. 設定條件：
   - 機動窗起點／終點（TCA 前幾分鐘）、最短通知時間（分鐘）
   - Δv 範圍（m/s）與 Δv 預算
   - 距離目標（km）、Pc 目標（只在傳播模式協方差時採用）
   - 網格：機動時刻數、Δv 量級數、驗證上限
   - 二次篩選追加物體：額外檢查的 NORAD 編號
3. 按「搜尋避碰方案」。

結果狀態：

| 狀態 | 意義 |
|---|---|
| 找到可行方案 | 列出建議方案（★）與其他通過驗證的候選 |
| 在指定網格內未找到方案 | 不代表不存在方案；可放寬目標、加大 Δv 或網格密度 |
| 限制條件互相衝突 | 例如通知時間之後已無合法機動時刻、預算小於最小 Δv |
| 不需機動 | 不機動的交會已符合目標 |
| 找不到目標交會事件 | 指定 TCA 附近沒有門檻內事件 |

候選方案表列出機動時刻、距 TCA（分）、方向（+T 抬升／−T 降低）、Δv、機動後距離、Pc 前後、軌道半長軸與週期變化、推進劑用量，以及「新增／變近交會」的二次篩選結果。

### 4. RPO 控制

2. 設定安全限制：安全區半徑（m）、接近速度上限（m/s）、走廊半角與軸向、被動安全圈數。

### 3. 💥 碎片連鎖：一顆衛星解體會引發連鎖碰撞嗎？

1. **選任務（可略過）**：自由實驗，或任務 1「自然清除」、任務 2「連鎖觸發者」、任務 3「守護者」。選任務後會自動帶入建議參數並顯示目標。
2. **選情境或衛星**：
   - 情境模板：Envisat 電池爆炸（假想），以及 3 個歷史情境：風雲一號 C 反衛星試驗（2007）、Iridium–Cosmos 碰撞（2009）、Cosmos 1408 反衛星試驗（2021）。歷史情境的母體已不在目錄中，以相同高度與傾角的單一圓軌道示意，名稱都標「教學近似」，**不是事件重演**（例如 Iridium 與 Cosmos 實際分屬不同軌道面）。
   - 或自選目錄中的衛星（搜尋 NORAD 編號或名稱），設定質量、碎片數、解體模型與模擬年數。
   - **解體模型要依事件性質選**：「爆炸模型」是衛星自身能量釋放（電池破裂、殘餘推進劑爆炸），碎片速度變化較小；「碰撞模型」是被外部物體高速撞擊（反衛星飛彈、衛星互撞），碎片散得較開。反衛星試射與衛星互撞一律用碰撞模型；情境模板與所選模型不一致時，畫面會提醒。解體後的所有碰撞都用碰撞模型。
3. **大氣與太陽活動起算日**：大氣預設「隨太陽活動」，依 10.7 cm 太陽電波通量 F10.7（1957 年起的實測，之後接預報到 2041 年，再往後以 11 年週期外推）決定高層大氣密度；太陽活動越強，大氣越膨脹，低軌碎片越快被拖下來（500 km 處高低可差約 25 倍）。也可選固定的低／中／高太陽活動，或舊版靜態大氣。「太陽活動起算日」決定 F10.7 從哪一天開始算，歷史情境會自動帶入事件日期（例如 Cosmos 1408 為 2021-11-15）；空白表示今天。注意它**只影響太陽活動**，背景的軌道目錄仍是現況，不是把整個模擬搬回歷史時間。2041 年以後的太陽活動是 11 年週期外推（情境假設，不是預報），走勢圖上以灰底標出。結果會列出模擬期間的 F10.7，風險儀表板也有 F10.7 走勢圖。實測期間另以每月「等效 Ap」計入磁暴讓大氣增密的效果。
   - **在軌衛星**：預設「維持軌道（保守假設）」，在軌衛星一直不衰減、持續避碰，長期風險可能偏高。可改選「平均 5 年／10 年後陸續失效」：每顆衛星在 0 到 2 倍平均壽命之間的某個時刻失效，之後受大氣拖曳、也不能再避碰（未計任務後主動離軌）。
4. **碰撞誇張倍率**預設「×1 寫實」。它只放大「碰撞截面」，讓凱斯勒連鎖在遊戲時間內看得到；不是把時間加速，也不是真實碰撞率。選誇張模式時，地球畫面上方會出現提示。
5. **緩解決策卡（選用，預算 3 點；三張都是教學簡化）**：
    - 🧹 清理任務（2 點）：在第 30 天、第 1 年或第 3 年，移除當時累計碰撞風險最高的 50 個碎片。
    - 🚀 移除廢棄火箭體（1 點）：立即或第 1 年，移除與母體軌道面相近（傾角差 ≤ 5°、升交點赤經差 ≤ 30°）、高度 ±100 km 內最接近的 10 個廢棄火箭體；符合條件的不足 10 個時，事件表會說明。
    - 🛰 避碰機動（1–2 點）：立即或第 1 年起，運作中的衛星對 ≥ 10 cm 的碎片避碰。能力分三級：基礎（碰撞機率降至 50%，1 點）、標準（10%，1 點）、進階（2%，2 點）。這是**簡化假設**，實際效果取決於預警、燃料、協調與虛警率；已失效的衛星不能避碰。預算不夠時，進階選項會停用。

    有選卡時，先顯示主結果，再自動跑一次「不採取決策」的**對照組**（同亂數種子、同取樣時刻），以**第一代碎片近似風險**比較效果：它是期望值，比單次擲中的碰撞次數更不受運氣影響，也不受偶發碰撞產生的後代碎片干擾；表中也列出累計期望碰撞。對照組沿用主結果的解體時刻，兩邊的衛星位置完全相同。圖表上的綠色虛線標出決策生效的時間。
6. 按「**引爆**」，再點「看前 3 小時」（碎片雲沿軌道拉成環）、「看前 90 天」（散成殼層）或「看全程」。

**怎麼看結果**

- 結果最上方標示「**統計模擬，不是碰撞預報**」：同樣參數換一個亂數種子，碰撞次數就可能不同。
- **第一代碎片近似風險**是判讀真實風險的主要數字：未加速情境下，第一代碎片撞上現有目錄物件的近似期望次數（誇張模式下略偏低）。誇張模式下另列「線性反推（偏高）」，因為多出的後代碎片也被算進去。
- 「怎麼看這個結果？」可展開三段說明：你看到的是什麼、什麼接近真實、什麼是誇張或簡化。
- 圖表的**橘色直線**是目前播放時間，**點圖例**可開關曲線。播放時碎片會隨大氣阻力逐漸下降（依後端記錄的衰減節點內插）；播放超過 30 天時，左下角會提示畫面軌道為近似，統計以模擬結果為準。
- **📊 風險儀表板**：風險最高的目錄物件、碰撞熱區高度帶、期末各代碎片比例、累計再入數。
- **事件表**：碰撞事件與決策卡生效的時間。
- **🎯 任務 3「守護者」**：固定為 Envisat、1,000 個碎片、寫實 ×1，第一代碎片近似風險降到對照組 81% 以下才算成功（79% 兩星、77% 三星）。判定用 5 個連續種子（決策組與對照組各跑一次）的中位數，約需 1 分鐘。即使用滿預算，通常也只能減少兩成多，這正是任務想傳達的重點：**預防解體比事後清除有效**。結果會說明失敗原因，並列出各種搭配的參考效果（機會成本）。
- **🏅 成就**：9 項，例如二次碰撞、失控增長（模擬後段碎片仍淨增長，碰撞產生的多於大氣清除）、大氣清道夫（碎片全數再入）、歷史學家（試過 3 個歷史情境）、任務 1–3。成就記在瀏覽器中。

> 模型重點：碎片依大氣阻力衰減再入；目錄中的火箭體與碎片也依 TLE 的阻力項衰減，在軌衛星（有效載荷）預設會維持軌道（可改選陸續失效）。寫實倍率下，單一解體事件很難在幾年內引發連鎖，碎片的危險在於長期累積。

> **驗證結果（Cosmos 1408 試射碎片，30 個種子中位數）**：用碰撞模型時，第 1 年的碎片存活比例與實際觀測一致（25.3%）；第 3 年 1.6%、第 5 年 0.4%（觀測 0.9%、0.2%），一年以後只**略偏高**，結果畫面會標示。v0.1.19 把碰撞模型中極端的碎片速度變化（Δv）截掉，讓遠地點很高、活太久的碎片變少；這是以這個事件校準的經驗修正，還沒有用其他事件獨立驗證。用爆炸模型則第 5 年仍剩 13.8%（觀測 0.2%），這也是兩種模型必須區分的原因。碰撞率尚未驗證。

**同時計算的限制**：同一時間只算一個碎片模擬，區網多人同時按「引爆」時，後按的人會看到倒數並自動重試；5 分鐘內用相同參數再按一次，會直接顯示上次的結果（標示「快取結果」）。

4. 地球畫面右上角的「從台北看太陽」以慢動作顯示氣球從日面前經過。

### 6. 🎯 強弓延伸：更強的火箭打得到衛星嗎？

1. 選目標衛星（預設 ISS，可搜尋）與發射點，調整燃燒結束速度。
2. 按「**找出交會機會（未來 12 小時）**」。交會表的所需速度：綠色＝目前速度到得了、紅色＝不足；點選一列看三個瞄準關鍵（時間、速度、預測）。
3. 按「播放飛行」看彈道與交會。播放過一次後，拖動「**發射時間誤差**」會即時重算脫靶距離與彈頭落點。

### 7. ♟ 太空兵棋：海纜中斷時，國際通訊撐得住嗎？

- 紅藍對抗加白方 GM，雙方同時下令、伺服器裁決；每回合 6 小時、共 8 回合、每方每回合 5 行動點。
- **開局**：選藍方、紅方由真人或 AI 擔任，以及你扮演的角色，按「開新推演」。
- **多人**：開局後出現藍方、紅方、白方的加入連結，在另一個分頁或電腦開啟。區網多人時，單機版要以 `--host 0.0.0.0` 啟動，連結中的 `127.0.0.1` 改成主機的 IP。
- **下令**：點行動按鈕加入本回合命令（滑鼠移上可看效果），需要目標的行動先選「目標海纜」，再按「**提交命令**」。面板上方的「💡 教練建議」會依局勢提示重點，可關閉。
- **結算**：每回合結束跳出結算視窗（可用率變化、海纜中斷數、本回合事件），按「繼續」進入下一回合。終局可看「**終局復盤**」：系統以蒙地卡羅跑 AI 四種打法各 300 局，與你這一局排名。
- **地圖**：藍綠實線＝正常、紅虛線＝中斷、橘虛線＝搶修中；距台灣 1,500 km 以外的段落較暗。
- **蒙地卡羅分析**：面板下方可直接比較 AI 藍方四種策略，數值為平均可用率與 95% 信賴區間。

> 兵棋為抽象模型：國際海纜每條 10 單位、離島海纜 1 單位、需求 150 單位起每回合 +5，數值為示意，不代表實際容量。

## 十三、帳號與權限（僅單機版）

- **尚未建立帳號時**不需登入：本機視為管理者，區網連線只能查詢。
- 在衛星管理的「帳號管理」由本機建立第一個管理者：需要輸入**一次性代碼**，代碼顯示在執行程式的主控台（黑色視窗）啟動訊息中，格式為 `XXXXX-XXXXX`（輸錯 10 次會換新代碼，新代碼同樣顯示在主控台）。這可防止惡意網站搶先建立管理者。
- 建立第一個管理者後，**所有頁面都需要登入**（登入狀態維持 12 小時，使用中會自動延長；同一帳號連續輸錯 5 次鎖定 60 秒）。管理者可再新增帳號、變更角色、停用或刪除帳號（至少保留一個管理者）。
- 右上角顯示目前帳號與角色，可變更密碼、登出。

| 角色 | 可以做什麼 |
|---|---|
| 檢視者 | 查詢、下載 CSV、執行過頂預報與交叉驗證 |
| 編輯者 | 再加輸入與修改：更名、群組、CSV 匯入、常用中心點、衛星屬性、觀測資料的新增修改刪除 |
| 管理者 | 再加帳號管理、觀測資料複核、星歷重抓、重載設定、程式更新 |

- 密碼以 Argon2id 雜湊保存，不存明文。
- **忘記管理者密碼**：關閉程式後刪除 `user_private\accounts.json`，即回到「尚未建立帳號」狀態；更名、群組與觀測資料不受影響。

## 十四、更新（單機版）

- 程式啟動 30 秒後自動檢查一次，之後每 6 小時檢查。
- 有新版時，地球儀右下角（任務規劃頁在頂列）顯示「資料庫有新版」或「程式有新版」與更新按鈕。
- **資料庫更新**：下載完成後自動換上新資料，不必重開程式；舊檔保留一份 `.bak`。資料庫每日更新，內含最新 TLE、SATCAT（再入日期）、GCAT、SATCAT 異動與 SupGP 營運商補充星曆。
- **程式更新**：下載完成後按「重新啟動」，新版會在新的主控台視窗啟動，頁面自動重新整理。
- 所有更新檔都經過數位簽章與 sha256 驗證，驗證不過就不會套用。
- 以 `--host 0.0.0.0` 開放區網時，只有本機（或已登入的管理者）可以觸發更新。

## 十五、常見問題

**Q1. 雙擊 exe 沒有反應或被擋下？**
SmartScreen 擋下時按「其他資訊」→「仍要執行」。公司電腦若禁止執行未簽章程式，請改用線上網頁版。

**Q2. 瀏覽器沒有自動開啟？**
看主控台視窗顯示的網址（例如 `http://127.0.0.1:5013/`），手動貼到瀏覽器。

**Q3. 地球一片藍或衛星沒有出現？**
第一次使用時資料庫還在下載，請等主控台顯示完成；頁面會自動重新整理。

**Q4. 資料庫下載中斷？**
重新啟動程式即可，會從中斷處續傳。也可以手動下載 `db/space_db_slim.duckdb.zst`，解壓到 exe 旁的 `data\DB\space_db_slim.duckdb`。

**Q5. 實驗室的碰撞機率可以直接用來決策嗎？**
不行。公開 TLE 的準確度有限，展示模式協方差是假設值。實際作業應使用精密星曆與營運方提供的協方差（例如 CDM）。

**Q6. 想換右下角 Logo？**
在 exe 同資料夾放 `logo.png` 或 `logo.jpg`（建議正方形、透明背景），重新整理頁面即生效；刪除檔案即恢復。

**Q7. 怎麼查目前版本？**
地球儀右下角的版本列，或在命令提示字元執行 `SatDashboard-x64.exe --version`。

**Q8. 線上版的更名、群組、觀測資料不見了？**
線上版這些資料只存在當下使用的瀏覽器。換電腦、換瀏覽器、使用無痕視窗或清除網站資料都會看不到。請定期在衛星管理「備份與匯入」、觀測頁「匯入匯出」下載備份；需要多人共用請改用單機版。

**Q9. 建議名稱可以直接當正式名稱用嗎？**
只有 official 是 Space-Track 的正式命名。inferred 與 group_inferred 都是推論，名稱會加「（推論）」，需要人工複核；group_inferred 只確認是哪次發射，不代表 OBJECT A 就是第一顆。

**Q10. 交叉驗證顯示「不符合」，代表觀測錯了嗎？**
不一定。可能是觀測時間或方向有誤、標錯 NORAD（看「同次發射比對」是否有更符合的物體）、目錄 TLE 太舊，或衛星做過機動。請對照提示與原始觀測紀錄再判斷。

**Q11. Space-Track 帳號安全嗎？**
在頁面輸入的帳號以明文存在 `user_private\spacetrack.json`。共用電腦上建議改用環境變數 `SPACETRACK_USER`／`SPACETRACK_PASS`，並限制該資料夾的存取權限。
